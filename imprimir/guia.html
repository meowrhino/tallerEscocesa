Taller de web autogestionada · La Escocesa

Cómo hacer y mantener tu web sin depender de nadie

Esta guía repite lo que hacemos en el taller, por escrito, para cuando estés sola delante del ordenador dentro de tres meses. No hace falta leerla entera de un tirón: busca el paso en el que estés.

00 Antes de empezar

Necesitas dos cosas instaladas y una cuenta creada:

  • Visual Studio Code — el programa donde escribes. Es un editor de texto, como un Word pero para código. Gratis, en code.visualstudio.com.
  • Un navegador — el que ya tengas.
  • Una cuenta de GitHub — gratis, en github.com. Ahí vive tu web para que la vea todo el mundo.

No necesitas pagar nada. No necesitas saber matemáticas. No necesitas la terminal.

01 Tu web es una carpeta

Esto es lo único que hay que creerse de verdad: una web es una carpeta con archivos de texto dentro. No hay nada más. La tuya se ve así: 

mi-web/
├── index.html      ← la portada
├── proyectos.html
├── cv.html
├── estilo.css      ← el aspecto de todas las páginas
└── img/
    ├── obra-1.jpg
    └── retrato.jpg

Guarda esa carpeta donde guardes tus cosas importantes. Si la mueves entera, sigue funcionando. Si sacas un archivo de dentro, se rompe.

Abrirla en VS Code

Archivo → Abrir carpeta, y eliges la carpeta entera. No abras los archivos sueltos: si abres la carpeta, ves toda tu web en la columna de la izquierda y puedes saltar entre archivos.

Verla en el navegador

Doble clic en index.html desde el escritorio, o botón derecho → Abrir con → tu navegador. Fíjate en que arriba no pone https:// sino una ruta de tu ordenador: todavía es una web privada, solo tuya.

Cada vez que guardes un cambio, recarga la página en el navegador para verlo.

02 Escribir el contenido (HTML)

El HTML dice qué es cada cosa: esto es un título, esto un párrafo, esto una imagen. Se escribe con etiquetas, que van en parejas: 

<h1>Tu nombre</h1>
<p>Una línea sobre ti.</p>
<img src="img/retrato.jpg" alt="Retrato en el taller">

Una abre y otra cierra, y la de cerrar lleva una barra. Lo que escribas entre medias es lo que se ve.

Añadir un proyecto nuevo

En proyectos.html, copia un bloque <article> entero, pégalo debajo y cambia el texto y el nombre de la imagen. Así de aburrido es. Así de fiable.

Añadir una página nueva

  1. Duplica cv.html y renómbralo, por ejemplo textos.html.
  2. Cambia el <title> y el contenido de <main>.
  3. Añade el enlace al menú de todas las páginas: <a href="textos.html">Textos</a>. Si solo lo pones en una, desde las demás no se llega.

03 Las imágenes

Tres reglas y ya está:

  1. Van dentro de la carpeta img/. Una imagen que esté en tu escritorio se ve en tu ordenador y en ningún otro sitio del mundo.
  2. El nombre, sin espacios, sin acentos, sin mayúsculas. Foto Taller.JPG falla al publicar; foto-taller.jpg no.
  3. Redúcelas antes de subirlas. Una foto de cámara pesa 8 MB y tarda una eternidad en cargar. Con 1600 píxeles de ancho y calidad media va sobrada: unos 300 KB. Con Vista Previa (Mac) o Paint (Windows) se hace en un minuto.

El alt no es opcional: es lo que lee en voz alta un lector de pantalla y lo que aparece si la imagen no carga. Describe lo que se ve, en una línea.

04 El aspecto (CSS)

Si el HTML dice qué es cada cosa, el CSS dice cómo se ve. Todo va en estilo.css, y una regla tiene esta forma: 

body {
  background-color: #fbfaf7;
  font-size: 18px;
}

El selector (body) dice a qué afecta; dentro van las propiedades. Punto y coma al final de cada línea.

La lista de propiedades está en la chuleta. La forma de aprender esto no es memorizarla: es cambiar un número, guardar, recargar y mirar. Cuarenta veces. No se rompe nada.

Robar ideas legalmente

En cualquier web que te guste: botón derecho → Inspeccionar. Ahí ves su HTML y su CSS. Mirar cómo está hecho algo es la manera normal de aprender esto, y no tiene nada de malo.

05 Publicarla

Hasta ahora tu web solo existe en tu ordenador. Para que exista en internet hay que copiar la carpeta a un servidor. Usamos GitHub, que es gratis y no te pide tarjeta.

  1. En github.com, botón New repository.
  2. Nombre: mi-web. Marca Public. Crear.
  3. En la página que sale, uploading an existing file.
  4. Arrastra el contenido de tu carpeta (los archivos y la carpeta img), no la carpeta que los contiene.
  5. Abajo, botón verde Commit changes.
  6. Pestaña Settings → Pages → en Branch elige main y guarda.
  7. Espera un minuto y recarga. Aparece tu dirección: tunombre.github.io/mi-web.
Si sale una página en blanco o un 404 Casi siempre es una de dos: el archivo no se llama exactamente index.html, o subiste la carpeta en vez de su contenido y ahora está todo un nivel más abajo. Entra en el repositorio y mira si ves index.html nada más abrirlo.

06 Actualizarla

Este es el paso que hace que la web sea tuya de verdad. El ciclo es siempre el mismo:

  1. Editas en tu ordenador, en VS Code.
  2. Guardas y lo compruebas en tu navegador, en local.
  3. Subes el archivo cambiado a GitHub: entras en el repositorio, Add file → Upload files, arrastras el archivo nuevo encima del viejo y Commit changes.
  4. Un minuto después está online.

Comprueba siempre en local antes de subir. Y guarda una copia de la carpeta antes de hacer cambios grandes: es la manera más simple de poder volver atrás.

07 Un dominio propio

tunombre.github.io/mi-web funciona perfectamente y es gratis para siempre. Si quieres tunombre.com, se compra aparte: entre 10 y 15 € al año en sitios como Porkbun, Namecheap o Gandi. Se conecta desde los ajustes del dominio, apuntándolo a GitHub.

El dominio se pone a tu nombre y con tu correo, siempre, aunque te lo configure otra persona. Es lo único de todo esto que se puede perder de verdad.

08 Cuando algo no funciona

Por orden, y funciona casi siempre:

  1. ¿Has guardado el archivo?
  2. ¿Has recargado la página? Prueba recarga forzada: Cmd+Shift+R (Mac), Ctrl+F5 (Windows).
  3. ¿Falta cerrar una etiqueta, una comilla, una llave o un punto y coma? VS Code te lo marca en color.
  4. Si es una imagen que no sale: el nombre del archivo y lo que pone en el src tienen que coincidir exactamente, incluidas mayúsculas y extensión.
  5. Botón derecho → Inspeccionar → pestaña Console. Si hay un error, está escrito ahí.
  6. Vuelve a la última copia que funcionaba y avanza otra vez desde ahí.

Si le preguntas a una inteligencia artificial, pídele que te explique el cambio, no solo que te dé el código, y pega solo el trozo que falla. Si le das la web entera te la devuelve reescrita de arriba abajo y dejará de ser tuya.

09 Seguir por tu cuenta

  • developer.mozilla.org — la documentación de referencia. Busca ahí cualquier etiqueta o propiedad.
  • neocities.org — miles de webs personales hechas a mano. Para mirar cómo están hechas y para no sentirse sola.
  • p5js.org — si quieres meter dibujo o animación hecha con código en tu web.
  • caniuse.com — si algo funciona en tu navegador pero dudas del resto.

Lo que has montado no caduca, no tiene suscripción y no se lo lleva ninguna empresa cuando cierre. Son archivos de texto en una carpeta: el formato más duradero que existe en internet.
