una web es una carpeta

No hay nada más. Ni servidores misteriosos, ni una empresa detrás, ni una suscripción. Archivos de texto dentro de una carpeta.

mi-web/
├── index.html      ← la portada
├── proyectos.html
├── cv.html
├── estilo.css      ← el aspecto
└── img/
    ├── obra-1.jpg
    └── retrato.jpg

En cualquier web que te guste: botón derecho → Inspeccionar. Eso que sale es todo lo que hay.

Si mueves la carpeta entera, la web sigue funcionando. Si sacas un archivo de dentro, se rompe.

qué es el html

Antes de escribir una sola etiqueta: qué es esto y qué hace exactamente.

00:10el concepto

html no dibuja: estructura

HTML son las siglas de HyperText Markup Language. Lo importante es la palabra del medio: markup, marcado. No es un lenguaje de programación — no calcula, no decide, no tiene memoria.

Lo único que hace es marcar un texto diciendo qué es cada parte: esto es un título, esto un párrafo, esto una imagen, esto un enlace.

Texto sin marcar

Rita Mestre
Trabajo con cerámica y sonido.
Cámaras sordas
2026 · Gres

El navegador no sabe qué es cada línea. Lo pinta todo seguido, igual.

El mismo texto, marcado

<h1>Rita Mestre</h1>
<p>Trabajo con cerámica y sonido.</p>
<h3>Cámaras sordas</h3>
<p>2026 · Gres</p>

Ahora sí. Y con esa información ya puede jerarquizarlo, y un lector de pantalla puede leerlo en voz alta con sentido.

la frase de hoy

El HTML dice qué es cada cosa. El CSS dice cómo se ve. Hoy solo hacemos lo primero. Va a quedar feo, y está bien que quede feo: el aspecto es la sesión que viene.

00:10por qué importa separar

por qué se separan las dos cosas

Porque el contenido dura y el aspecto cambia. Dentro de cinco años querrás otra tipografía, otros colores, otra distribución — pero tu bio y tus proyectos van a ser los mismos.

Si están separados, rediseñas la web entera tocando un solo archivo y sin abrir el contenido. Lo verás en la sesión 2: el mismo HTML, cuatro webs distintas.

Y porque hay lectores que no son ojos: buscadores, lectores de pantalla, el modo lectura del móvil. Todos leen la estructura, no el aspecto.

Un <h1> escrito como <h1> es un título para todo el mundo. Un texto puesto grande a mano solo es un título para quien lo ve.

00:20 · 20 minutos

cómo es una web por dentro

La carpeta, los nombres de archivo, las rutas, y el entorno de trabajo.

00:20

tres cosas que hay que creerse

  1. La carpeta es la web. Si la mueves entera, sigue funcionando. Si sacas un archivo de dentro, se rompe.
  2. index.html es la portada. Ese nombre exacto: es el que busca el servidor por defecto cuando alguien entra sin pedir ninguna página concreta.
  3. img/obra.jpg significa «dentro de mi carpeta». Una imagen que esté en tu escritorio se ve en tu ordenador y en ningún otro sitio del mundo.
nombres de archivo

Sin espacios, sin acentos, sin ñ, sin mayúsculas. Foto Taller.JPG falla al publicar; foto-taller.jpg no.

Y ojo: para un servidor, .jpg y .JPG son archivos distintos. En tu Mac funciona igual y al publicar deja de funcionar. Es el fallo número uno del taller.

00:20el entorno

abrir la carpeta, no el archivo

En VS Code

Archivo → Abrir carpeta, y eliges la carpeta entera. Nunca un archivo suelto.

Así ves toda tu web en la columna de la izquierda y puedes saltar entre archivos.

En el navegador

Doble clic en index.html. Fíjate en que arriba no pone https:// sino una ruta de tu ordenador: todavía es una web privada, solo tuya.

VS Code   →   guardas   →   Navegador   →   recargas   →   ves el cambio

Coloca las dos ventanas lado a lado. Este bucle es el 90% del trabajo, hoy y siempre.

las etiquetas van en pareja

<p>Esto es un párrafo.</p>
 ↑ abre                ↑ cierra (lleva barra)

Lo que escribes entre medias es lo que se ve. Y lo que anides dentro, se cierra dentro:

<article>
  <h3>Cámaras sordas</h3>
  <p>2026 · Gres y grabaciones de campo</p>
</article>
00:40el esqueleto

la estructura de una página

<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">                          acentos y ñ
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Rita Mestre</title>                     la pestaña
  <link rel="stylesheet" href="estilo.css">      el aspecto
</head>
<body>
  <header> tu nombre y el menú </header>
  <main>   el contenido propio de esta página </main>
  <footer> contacto, créditos </footer>
</body>
</html>

head es lo que no se ve. body es lo que sí.

00:40

títulos y párrafos

<h1>Rita Mestre</h1>          el título principal
<h2>Proyectos</h2>            un apartado
<h3>Cámaras sordas</h3>       algo dentro del apartado

<p>Un párrafo.</p>
<p>Otro párrafo, con otra idea.</p>
un solo h1 por página

h1 a h6 es jerarquía, no tamaño. El tamaño se decide luego, en el CSS. No uses un h4 porque quieras letra pequeña: usa el nivel que le toca y ya lo harás pequeño después.

00:40

enlaces

<a href="cv.html">CV</a>                      a otra página tuya
<a href="https://neocities.org">Neocities</a>  a otra web
<a href="mailto:rita@ejemplo.com">Escríbeme</a>  abre el correo

href es a dónde va. Lo que escribes entre las etiquetas es lo que se ve y se puede clicar.

para una web de fuera

Hace falta el https:// delante. Sin eso el navegador lo busca dentro de tu carpeta y da 404.

00:40

imágenes

<img src="img/obra-1.jpg" alt="Cinco piezas de gres sobre una mesa">
  • src es dónde está el archivo. img/ significa dentro de tu carpeta.
  • alt describe la imagen: lo lee en voz alta un lector de pantalla y aparece si la imagen no carga.
  • No lleva etiqueta de cierre. Es de las pocas.
el alt no es opcional

Descríbela en una línea, como se la describirías por teléfono a alguien. No pongas «foto» ni el nombre del archivo.

añadir una página

  1. Duplica index.html y llama a la copia proyectos.html.
  2. Cambia el <title> y vacía el <main>.
  3. Añade el enlace al menú de todas las páginas, no solo de una.
<nav>
  <a href="index.html">Inicio</a>
  <a href="proyectos.html">Proyectos</a>
  <a href="cv.html">CV</a>
</nav>
el fallo típico

Añadir el enlace nuevo solo en una de las dos páginas. Desde la otra no se llega, y parece que el enlace está mal cuando lo que falta es repetirlo.

Sí: el menú se copia entero en cada archivo. Es aburrido y es normal.

02:40lo que no vamos a hacer

lo que esto no hace

Mejor saberlo ahora que a las dos horas:

formulario de contactoNecesita un servidor. Pon tu correo con mailto: — es lo que hace casi todo el mundo y no se rompe nunca.
tiendaPagos, stock y seguridad son otro proyecto. Enlaza a Bandcamp o Big Cartel.
blog automáticoCada entrada es un archivo que creas a mano. Para tres o cuatro al año, perfecto. Para escribir cada semana, cansa.
comentariosNecesitan base de datos y moderación. No.
reservas / calendarioEnlaza a una herramienta externa.

Lo que sí hace: existir para siempre, cargar rápido, no costar nada al mes y no depender de ninguna empresa.

ejercicio 31 hora · en casa

deberes: reunir el material

No hay que programar nada. Es preparar el contenido, que es la parte que más tarda y la que no se puede improvisar en clase. Sin esto, la sesión 2 no cunde.

Textos

  • Tu bio, escrita y revisada.
  • La ficha de cada proyecto: título, año, técnica, lugar, dos o tres líneas.
  • Tu CV: exposiciones, formación, lo que quieras incluir.

Referencias

  • Dos o tres webs que te gusten. Apunta de cada una qué te gusta: ¿el tamaño de letra? ¿el blanco? ¿los colores?

Imágenes

  • Entre 5 y 10, en una carpeta.
  • Reducidas a unos 1600 píxeles de ancho, con Vista Previa, Paint o squoosh.app.
  • Renombradas: sin espacios, sin acentos, en minúsculas. obra-2024.jpg, no Obra 2024.JPG.
ojo con el peso

Una foto recién salida de la cámara pesa 8 MB y tarda una eternidad en cargar. Reducida son 300 KB y se ve exactamente igual en pantalla.

chuleta · html

Estructura de la página

<html>Todo el documento va dentro.
<head>Lo que no se ve: título de la pestaña, enlace al CSS.
<body>Lo que sí se ve.
<header>Cabecera: tu nombre y el menú.
<main>El contenido propio de cada página.
<footer>Pie: contacto, créditos.
<article>Una unidad suelta: un proyecto, una obra.

Enlaces e imágenes

<a href="cv.html">Enlace a otra página de tu web.
<a href="https://…">Enlace a otra web. Necesita el https:// delante.
<a href="mailto:…">Enlace que abre el programa de correo.
<img src alt>Imagen. alt la describe para quien no la ve.

Contenido

<h1> … <h6>Títulos, de más a menos importante. Un solo h1 por página.
<p>Un párrafo. Uno por idea, no uno para todo el texto.
<br>Salto de línea suelto. No lleva cierre. Úsalo poco.
<em> <strong>Cursiva y negrita.
<ul> <li>Lista. ul es la lista entera, cada li una línea.
<hr>Línea de separación.
<!-- … -->Comentario: no se ve en el navegador.

Si algo no funciona

  1. ¿Has guardado el archivo?
  2. ¿Has recargado? Recarga forzada: Cmd+Shift+R o Ctrl+F5.
  3. ¿Falta cerrar una etiqueta o una comilla? VS Code lo marca en color.
  4. ¿Una imagen no sale? El nombre del archivo y el src tienen que coincidir exactamente, mayúsculas y extensión incluidas.
